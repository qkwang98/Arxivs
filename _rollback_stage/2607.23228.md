# Directed Homotopy, Sectional Invariants, and Functorial Databases
keywords: directed homotopy, Grothendieck construction, sectional category, functorial database, opfibration, topological complexity
related_paper: Spivak, "Functorial Data Migration"
one_liner_summary: 将有向同伦论与函子数据库统一，建立数据库实例为离散 Grothendieck opfibration 的范畴模型，并用 sectional invariants（dcat, dsecat）刻画数据迁移复杂性。

## 🎯核心定位
1. **核心问题**：将函子数据库理论（functorial databases）与有向同伦论（directed homotopy）统一，用 sectional invariants 刻画数据迁移的拓扑复杂性。
2. **与其他文献的关系**：基于 Spivak 的函子数据迁移框架，利用 Grandis 有向同伦论和 Fajstrup-Goubault-Haucourt-Mimram-Raussen 的有向拓扑复杂性理论，提出范畴层面的系统化衔接。
3. **主要贡献**：证明数据库实例范畴 dB 等价于离散 Grothendieck opfibration 的范畴；定义有向截面不变量 dcat 和 dsecat；利用截面存在性判断函子数据迁移可行性；建立 indexing 函子与 opfibration 的对应定理。
4. **技术难点**：有向同伦与离散 opfibration 的精确对应；截面不变量在有向情形下的正确定义（需要考虑反链和不可逆态射）；dcat 和 dsecat 的可计算性。
5. **方法**：范畴论的 Grothendieck 构造；有向同伦的 d-空间和 dipath 范畴；离散 opfibration 与数据库 schema 函子的等价性。
6. **局限性**：主要处理离散 opfibration（对应无缺失迁移），一般 cofibration 和更复杂的 schema mapping 未充分处理。
7. **可扩展方向**：高阶范畴的函子数据库（∞-categories）；真实 RDF 数据库的 dcat 计算工具。

## 📐主要定理
**Theorem (Grothendieck 对应)**：数据库实例的范畴等价于某 schema 函子的 Grothendieck 构造所给出的离散 opfibration 范畴。即 dB ≅ dOpFib(B)，其中 B 为 schema 范畴。

**Theorem (截面存在性 = 迁移可行性)**：函子 F: C → D 对应的数据迁移可行的充要条件是存在从 D 到相应 Grothendieck 构造的截面。

**Theorem (dcat 下界)**：dcat(X) ≤ dsecat(X) ≤ dcat(X) + 1（在有向情形下类似于 Lusternik-Schnirelmann 型不等式）。

## 🔑关键组件
- **Grothendieck opfibration**：将 I-指标化族编码为纤维化范畴上的构造；离散 opfibration 对应集合值函子。
- **Discrete opfibration**：所有 lift 唯一的 opfibration，对应从基范畴到 Set 的函子（即数据库实例）。
- **截面 (section)**：函子 ∫F → C 的右逆，对应于全局一致的数据选择。
- **dcat (directed category)**：有向 Lusternik-Schnirelmann 范畴——测量覆盖空间所需的有向可缩开集的最小数。
- **dsecat (directed sectional category)**：有向截面范畴——测量使截面存在所需覆盖的最小数。
- **Indexing 函子**：将数据 schema 映射到数据类型的函子 J: S → D，其 Grothendieck 构造给出数据库实例的具体形式。

## 💡理解辅助
1. **函子数据库的核心思想**：schema 为小范畴 S，实例为函子 S → Set。不同 schema 间的迁移为 Kan 扩张。Grothendieck 构造将函子 S → Set 转化为 S 上的离散 opfibration。
2. **有向同伦的切入**：将 schema morphisms 视为有向路径（不可逆），数据库的索引选择视为截面。dcat/dsecat 测量"需要多少次索引切换才能完整覆盖数据空间"。
3. **可视化**：schema 为有向图，实例为每个节点上的数据表（离散纤维）。opfibration 的 cartesian lift 对应外键约束的满足。截面为"在所有表中选一行的一致性赋值"。

## ✏️主动思考区
- dcat 不变量是否能区分 NoSQL 和关系型数据库的 schema 表达能力？
- 有向同伦中的 "directed homotopy equivalence" 是否对应数据库 schema 的某种双解释 (bi-interpretability)？
