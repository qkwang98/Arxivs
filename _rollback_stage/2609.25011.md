# A Kernel-Certified Verification of the Erdős–Mollin–Walsh Conjecture below $10^{14}$

keywords: [powerful numbers, Lean 4, 形式化验证, Erdős–Mollin–Walsh 猜想, 证明核]
related_paper: "google-deepmind/formal-conjectures"
one_liner_summary: "利用 Lean 4 证明核端到端验证了 Erdős–Mollin–Walsh 猜想在 $10^{12}$ 与 $10^{14}$ 以下不存在三个连续 powerful 数，且不依赖任何可信的枚举代码。"

## 1.  核心定位

- **解决的问题**：Erdős 问题 364（Erdős–Mollin–Walsh 猜想）断言不存在三个连续的 powerful 数；本文首次在有限界 $10^{12}$ 与 $10^{14}$ 下给出经证明核端到端检验的机器可验证证明。
- **大图景位置**：这是该猜想在任意有限界下的首个核验证结果；它不是计算记录（非认证计算已穷尽至 $10^{22}$），而是将证据链中可信枚举代码彻底消除。
- **主要贡献**：
  1. 两个 Lean 4 定理（$10^{12}$ 与 $10^{14}$ 以下无连续 powerful 三元组），公理足迹恰为 $\{\text{propext}, \text{Classical.choice}, \text{Quot.sound}\}$，无 sorry、无 native\_decide、无自定义公理；
  2. 证明架构：一次性证明的参数化可靠性定理加上数千个小布尔证书，使单进程核内存有界（$\le 7.9$ GB），而单体式 decide 在 $10^9$ 以下即失败；
  3. reference-table 优化：将每个证书最昂贵的平方自由性重测摊销为单张核验证表，实测端到端加速 $23.8\times$，使 $10^{14}$ 档可行（约 30 CPU 小时）；
  4. 双实现证书方法论：每个证书的期望值由独立 Python 引擎计算，核验证的等式同时是跨实现一致性检验；
  5. 语句级桥接：抽象地证明上游开放猜想蕴含每个有界定理，使被验证的结论恰是猜想的有限片段。
- **关键先驱工作**：Erdős (1976) 与 Mollin–Walsh (1986) 独立提出的猜想；Guy 的 Unsolved Problems in Number Theory 之 B16；Bloom 的 Erdős 问题目录第 364 题；$abc$ 猜想蕴含至多有限个三元组；Donovan Johnson 2011 年对连续 powerful 对的枚举（OEIS A060355）；google-deepmind/formal-conjectures 对问题 364 的规范形式化。
- **结果边界**：仅覆盖 $n+2 \le 10^{14}$ 的有界情形；更大的非认证计算（穷尽至 $10^{22}$，条件性至约 $7.38 \times 10^{28}$）未被核验证；无界情形下猜想仍然开放。
- **开放问题**：无界情形仍开放；进一步推高核验证界（如 $10^{16}$ 或更高）需要更多核计算时间；OEIS A076445 的完备性至今未建立。
- **应用与推广**："参数化可靠性定理加小证书"的架构可迁移到其他依赖大规模穷举的数论猜想的机器验证；双实现证书方法论可降低形式化验证中可信基的怀疑。

- 技术迁移：把"一次证明加千个小证书加独立引擎双实现"的模式迁移到其他依赖大规模计算的猜想（如哥德巴赫型验证、素元组筛法），可以显著降低对可信代码的依赖。

### 2.3.  批判性思考

- 证明依赖 Lean 4 与 mathlib 自身的可靠性（元理论信任）：核验证消除了枚举代码的可信负担，但并未消除对证明助手内核的信任，这是所有交互式证明工作的固有边界。
- 每个证书的期望值由独立 Python 引擎计算，虽然提供了跨实现一致性，但 Python 引擎本身的正确性并不在核验证范围内。
- 公理足迹报告依赖 #print axioms 的正确性以及 CI 中的 axiom gate 纪律；冻结纪律是否在所有构建路径上都被严格执行值得关注。
